## Purpose

Mount governed projects into the Ω aggregation fabric without transferring source authority.

```text
SOURCE WORLD
-> MOUNT
-> REVISION MAP
-> DEEP MAP
-> ProjectHarvestCapsule
-> KnowledgeQuantum
-> provenance / authority / license gate
-> LatticeAdmission
-> Knowledge Lattice
-> Holotope
-> Archetonic Plate
-> Kernel / Skill Composition
-> Execute / Verify / Witness
-> FeedbackPacket
-> SOURCE WORLD
```

The “black hole” metaphor is accepted only as a high-density ingestion/compression metaphor.

```text
BLACK_HOLE != SOURCE_ERASURE
MOUNT != OWNERSHIP_TRANSFER
COMPRESSION != AUTHORITY_PROMOTION
CENTRALITY != AUTHORITY
VECTOR_SIMILARITY != IDENTITY
GLOBAL_FEEDBACK != AUTOMATIC_SOURCE_MUTATION
```

## Mount invocation

A host that can resolve a canonical project folder or repository may use:

```text
MOUNT::SOURCE_ROOT=<canonical project root>
MOUNT::OMEGA_ROOT=<configured Omega aggregation root>
MODE::DEEP_MAP+DELTA_HARVEST
NEXT()
```

The local project contract is resolved first:

1. START / CONTINUE
2. STATE / HANDOFF
3. AGENTS / constitution
4. Drive/GitHub authority split
5. active lineage / release
6. local frontier
7. prior harvest capsule
8. changed frontier

The Ω aggregate is a second root, never an authority shortcut.

## ProjectMount

A mount records identity, roots, lineage, authority, access mode, publication/license boundaries, source revision set, prior capsule, lattice parent and open gates.

Read access never implies write authority.

## HarvestSession

First mount establishes a bounded project map.

Later sessions are delta-first:

```text
previous revision set
-> changed sources
-> dependency impact
-> changed frontier map
-> capsule delta
-> lattice admission
-> affected holotope/plate recompute
-> receipt
```

Full re-ingestion is reserved for authority/lineage/root changes, dependency invalidation, corruption, ambiguity or explicit audit.

## KnowledgeQuantum

A quantum is the smallest reusable unit that retains:

- stable semantic identity;
- provenance;
- scope/assumptions;
- evidence/status class;
- dependencies;
- contradictions/negative results;
- authority ceiling;
- publication/license boundary.

Typical classes: Definition, Law, Invariant, Schema, Algorithm, Method, Skill, KernelContract, APIContract, Protocol, TestVector, Claim, Evidence, Measurement, TheoremTarget, TheoremResult, NoGo, FailureMode, Contradiction, Dataset, Experiment, ObserverModel, Capability, Receipt, Release, ExternalAnchor.

## FeedbackPacket

The aggregate may return reusable improvements to a source project as a candidate packet:

- METHOD_UPGRADE
- KERNEL_REUSE
- SCHEMA_ALIGNMENT
- TEST_ADDITION
- FORMAL_OBLIGATION
- SECURITY_HARDENING
- RELEASE_HARDENING
- CONTEXT_COMPACTION
- ONTOLOGY_ALIGNMENT
- PROVENANCE_FIX
- CONTRADICTION_ALERT
- SUPERSESSION_ALERT

The source project must explicitly accept, modify, reject or defer the packet.

## Work-first rule

Aggregation must run beside real project work.

```text
SOLVE_LOCAL_PROBLEM
-> MAP/HARVEST reusable structures while solving
-> capsule delta
-> lattice admission
-> later retrieve qualified global improvements
```

The source project remains productive.
