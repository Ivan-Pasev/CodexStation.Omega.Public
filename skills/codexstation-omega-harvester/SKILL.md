# CodexStation Ω Harvester

## Use when
- a canonical project folder or repository is mounted;
- the user asks to deep-map, harvest, metabolize, crystallize, aggregate, or prepare a project for Ω intake;
- a large corpus must be compressed into reusable typed knowledge while keeping provenance and status.

## Boot order
1. project START/CONTINUE;
2. project STATE/HANDOFF;
3. project AGENTS/constitution;
4. canonical source/repository authority split;
5. aggregation protocol and schemas;
6. only the additional sources needed to map the current frontier.

## Pipeline
```text
SCAN
-> MAP
-> SOURCE-FINGERPRINT
-> CLASSIFY
-> OBJECTIZE
-> DEDUP
-> ALIAS/SUPERSESSION
-> RELATE
-> EVIDENCE-TYPE
-> AUTHORITY-CEILING
-> LICENSE/IP-GATE
-> QUANTIZE
-> LATTICE-ADMIT
-> HOLOTOPE
-> ARCHETONIC-PLATE
-> KERNEL/SKILL-ROUTE
-> CRYSTALLIZE
-> WITNESS
```

## Output
Prefer one dense ProjectHarvestCapsule per project/epoch plus deltas.

## Guards
```text
SOURCE_PROJECT_CANON != OMEGA_AGGREGATE_VIEW
BLACK_HOLE != SOURCE_ERASURE
COMPRESSION != AUTHORITY_PROMOTION
VECTOR_SIMILARITY != IDENTITY
LATEST != AUTOMATIC_AUTHORITY
SAME_LABEL != SAME_LINEAGE
CLAIM != EVIDENCE
FORMAL_PROOF != EMPIRICAL_CONFIRMATION
SKILL != HOST_CAPABILITY
```

## Kernel extraction
Prioritize deterministic, reusable primitives:
identity, canonical serialization, transition, authority, admission, invariants, event sourcing, replay, rollback, witness, conflict, context compilation, sandbox/provider ABI, projection, verification and release.

## External code
Source/license audit before reuse. Prefer wrap/adapt/clean-room refabrication over blind forking.

## NEXT()
After the first complete map, use revision-aware delta ingestion rather than rereading the whole project.

No harvest cycle may close unrelated live-host or scientific gates.
