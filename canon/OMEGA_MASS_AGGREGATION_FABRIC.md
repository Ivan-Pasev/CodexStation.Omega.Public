## 4. Canonical intake object

Every source project converges toward a `ProjectHarvestCapsule`.

The capsule carries project identity, source map, authority split, lineages, active frontier, releases, objects, relations, evidence, kernels, skills, contradictions, negative results, open gates, quarantine, candidate global deltas and next target.

The capsule is the portable boundary between local project sovereignty and global reuse.

## 6. Knowledge lattice

The lattice is a typed, versioned graph of admitted objects and relations.

Recommended strata:

```text
L0 constitutional primitives
L1 identity / authority / provenance
L2 claims / evidence / gates
L3 knowledge objects
L4 methods / skills / kernels
L5 execution / capability
L6 project / theory / domain
L7 artifacts / releases
L8 negative knowledge / contradictions
L9 external anchors
```

Status and authority remain explicit fields. Graph centrality never defines truth.

## 7. Holotope

A Holotope is a mission-bounded coherent subgraph compiled from the lattice.

It includes the minimum useful set of objects, source pointers, invariants, skills, kernels, capabilities, evidence, open gates and negative knowledge needed for one mission.

```text
HOLOTOPE != WHOLE_CANON
HOLOTOPE != NEW_AUTHORITY
```

Holotopes solve context-window and source-count constraints without forking canon.

## 8. Archetonic Plate


The Plate is the bridge from accumulated knowledge to practical engineering, research and release work.

## 12. Provider projection

Provider packages may differ in source count, organization, boot instructions and runtime adapters.

They may not silently diverge in admitted semantic objects, IDs, authority/evidence laws or lineage semantics.

The public aggregation fabric is intended to compile into ChatGPT/Codex, Gemini Notebook and later provider profiles from one provider-neutral semantic parent.
